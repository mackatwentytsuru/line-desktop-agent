# LINE デスクトップ・エージェント 設計(2026-11-10 本人承認)

## 目的
大和の LINE for PC(Windows 11)を Claude Code から読み、まとめ・探す・やること拾い・返信の下書きをし、本人が確かめたときだけ送る。非公式の通信(OkLine など)は使わない。11-10 14:46 の事故(キーがデスクトップに入り全消去)を二度と起こさない。

| 使い道 | まとめ・追いつき/探す/返信の下書き/やること・予定の拾い出し |
| 送信 | 毎回、Claude の画面で相手と文面を確かめて「はい」のときだけ |
| きっかけ | 新着が来たとき |
| PC を使っている最中 | 読むだけなら動いてよい。トークを開くクリック相当も「いつでもよい」 |

| 機械 | 今は大和。いずれ別の PC へ移せる作りにする |

## 今日わかった事実(読むだけで実測)
- LINE は Qt 6.6.3 製。Windows の読み上げ用の情報(UI Automation)に**本文がそのまま出ている**。キーもクリックも前面の切り替えも無しで読めた。
  - トークの窓(ChatWindow「一括送信」)→ List の中に Text として「日付」「本文」「写真, 午後 1:45」「ファイル, 期限切れ, ○○.pdf」などが並ぶ。
  - 本体の窓(AllInOneWindow)→ トーク一覧の各行が Button で「名前, 未読数, 最後の一言, 時刻」。**未読数が読める**ので、これを「新着の知らせ」に使える。
  - 一覧の行・送信まわりのボタンは Invoke(押す)に対応、入力欄は Value(文字を入れる)に対応 → **キーを打たずにトークを開き、文字を入れる道がある**(送信ボタンの有無と、入れた文字が LINE に効くかは未確認)。
- 「トーク, 347」= 未読の合計も読める。

## やり方の比べ
| 方法 | 良い所 | 悪い所 | 判断 |
|---|---|---|---|
| UI Automation で読む(キーなし) | 前面を奪わない・本人の作業中でも安全・既に本文が取れた | 画面に読み込まれた分だけ。LINE の更新で部品名が変わり得る | **採用(中心)** |
| UI Automation の Invoke / Value で開く・入れる | キーを使わない | 窓が前に出る可能性。効くか未確認 | 採用(試験してから) |
| トークの TXT 保存(LINE 標準) | 公式・全履歴 | 手作業、毎回本人の操作 | 補助(過去の一括取り込みに使う) |
| 画面写真 + OCR | どんな画面でも | 誤読・重い | 予備(UIA で取れない画像の説明だけ) |
| キー操作(AutoHotkey など) | 何でもできる | 今日の事故の原因 | **原則使わない**。どうしても要る 1 か所だけ、前面の窓を毎回確かめてから |
| 公式 Messaging API | 正規 | 個人トークは読めない | 対象外(公式アカウントを作るときだけ) |

## 推す作り
Python(このリポジトリの中の venv。PC 全体には入れない)で、小さな MCP サーバーとスキルを作る。

```
line-desktop-agent/
  src/line_agent/
    uia.py        LINE の窓を探す・木を読む(読むだけ)。窓は「プロセス名 LINE + 窓の種類 ChatWindow/AllInOneWindow」で特定
    reader.py     トーク一覧(名前・未読・最後の一言・時刻)と、トークの本文を取り出す
    store.py      SQLite に保存(重複は捨てる)。置き場所 %LOCALAPPDATA%\line-desktop-agent\(git の外)
    watcher.py    30 秒ごとに一覧の未読数を読むだけ → 増えたら本文を取り込み → 知らせ
    opener.py     一覧の行を Invoke で開く(キーなし)。開いた後、前面の窓を元に戻す
    sender.py     送信(下の安全の決まりをすべて満たしたときだけ)
    mcp_server.py Claude Code 用の道具: line_list_chats / line_read_chat / line_search / line_open_chat / line_send
  .claude/skills/line/SKILL.md   使い方(まとめ・探す・下書きの手順)
  tests/   部品の木の「にせもの」を使った試験(本物のトーク本文は入れない)
  docs/設計.md
```

- **「新着が来たとき」** = watcher が一覧の未読数の増加を見張る(Windows の通知そのものは読まない。権限も要らず、確実)。
- **まとめ・やること** = 新着を Claude に渡して作る。重い量のときは、本人の許しどおり安い AI(GLM・DeepSeek)に回してもよい。
- **スマホへ** = Claude アプリの通知。watcher から直接は送れない可能性があるので、段階 3 で「背景の Claude から通知が出せるか」を確かめる。出せなければ、そのとき本人に別の道を聞く。
- 別の PC へ移すとき: 窓の探し方・保存先・間隔を設定ファイルにまとめ、コードは機械に依存させない。

## 安全の決まり(コードで守る)
1. **キーを打たない。** 読む・開く・文字を入れる、すべて UI Automation の Invoke/Value で。SendKeys・AutoHotkey は使わない。
2. Ctrl+A・Delete・取り消し・送信取り消し・退会・設定の変更は、**道具として作らない**。
3. 送信の前に毎回すべて確かめる。1 つでも合わなければ止める:
   - 送り先の窓の題名 = 本人が「はい」と言った相手の名前(完全一致)
   - その窓のプロセスが LINE、窓の種類が ChatWindow
   - 入力欄に入った文字 = 確認した文面(読み戻して比べる)
   - 入力欄が最初は空(本人の書きかけを消さない。空でなければ止める)
4. `line_send` は Claude Code の許可設定で「毎回たずねる」にする + 道具の中でも相手・文面を画面に出してから送る。2 重の確認。
5. どうしても Enter キーが要ると分かった場合だけ: 押す直前に前面の窓が目的の ChatWindow かを確かめ、1 回だけ。違えば何もしない。
6. 非常停止: `%LOCALAPPDATA%\line-desktop-agent\STOP` があれば全部止まる。送信は許可リスト(config.json の send_allowlist。最初は自分だけのテスト用トーク)の相手しか許さない。
7. 開くときに LINE が前に出たら、すぐ元の窓へ戻す。本人が文字を打っている最中(直近 3 秒に入力)は開くのを待つ(打った文字が LINE に入るのを防ぐ)。
8. 保存は %LOCALAPPDATA% の下だけ。git には本文を入れない(.gitignore と試験で確かめる)。
9. 記録: 送ったもの・開いたトークを日時つきでログに残す。

## 段階と試験
| 段 | やること | 合格 |
|---|---|---|
| 0 | `docs/設計.md` をコミット | 本人の OK |
| 1 | 読むだけ: 一覧と「一括送信」の本文を取る | にせもの木の試験が通る/本物で一括送信の最新 20 件が画面と一致。前面の窓が一度も変わらない(前後で記録して比べる) |
| 2 | 見張り + 保存 + 探す + まとめ | スマホから一括送信に書く → 1 分以内に取り込まれ、Claude で探せる |
| 3 | スマホへの知らせ | 一括送信の新着 → Claude アプリに通知が届く |
| 4 | 開く(Invoke) | 一覧から一括送信を開ける。最小化中・別アプリ操作中でも、キーが他へ入らない |
| 5 | 送る(一括送信だけ) | 相手名違い・欄が空でない・文面違いの 3 つの「わざと間違い」で必ず止まる。正しいときだけ届く |
| 6 | 全部のトークへ広げる | 本人の OK のあと。送信の 2 重確認はそのまま |

- 試験で本物に触るのは「一括送信」だけ(段 6 まで)。
- 実装は作業役(Codex・Claude の実行役)に回し、司令塔が差分を全部見る。本文を含まないにせものデータで作らせる。
