# 送信・開く・スクロールの決まり(段 7、2026-11-10)

**すべて裏で動く。** マウスを動かさない・物理のキーを押さない・LINE の窓を前に出さない。本人は、その間も別のアプリで打ち続けてよい(本人の操作が止むのを待つ必要もない)。

## 使い方
- 開く: `python -m line_agent open <トーク名>`(名前は完全一致。同じ名前が 2 つあれば止まる)
- 送る(2 回に分ける):
  1. 下見: `python -m line_agent send 一括送信 --text "文面"` → 相手・窓の番号・文面と、合言葉(5 分で切れる・1 回だけ)が出る
  2. 本番: `python -m line_agent send 一括送信 --text "同じ文面" --confirm <合言葉>`
- スクロール: `scroll <トーク名> --up N | --down N | --to-bottom`
- 古い履歴の読み込み: `history <トーク名> [--until-date YYYY-MM-DD]`(上へ送り、日付に届くか先頭が動かなくなったら止めて保存)
- 記録を見る: `ledger`。目で確かめたら `ledger-resolve <id> sent|failed`

## どうやって動かすか(実測で決めた)
| 操作 | やり方 | 前に出るか |
|---|---|---|
| 文字を入れる | 入力欄に LegacyIAccessible で値を入れる | 出ない(ValuePattern や UIA のフォーカスは前に出るので使わない) |
| 送る | LINE のトークの窓へ Enter のメッセージ(WM_KEYDOWN / WM_KEYUP)を投函 | 出ない。窓への投函なので、ほかのアプリには届かない |
| スクロール | トークの窓へホイールのメッセージ(WM_MOUSEWHEEL)を投函 | 出ない |
| 開く(最小化中) | 前に出さずに戻す(SW_SHOWNOACTIVATE) | 出ない |
| 開く(窓なし) | 一覧の行を UIA で押す | LINE が前に出すことがある → 守りがすぐ本人の窓へ戻し、記録に残す |
| 添付の確かめ | `save <トーク名> --match <行の一部>`: 行を探し、期限切れは断り、保存済みか・ダウンロードのどこにあるかを返す(画像は PrintWindow で読むだけ) | 出ない |
| 添付の保存 | **PC 版ではできない**(下の「できないこと」、段 8)。Chrome 版ならできる(docs/Chrome版の使い方.md) | — |

## 送れる相手
- 送れるのは、データ置き場の `config.json` の `send_allowlist`(トーク名の一覧)にある相手だけ。**空か無ければ送信は無効**(下見がその旨と有効にする方法を返す)。コードには送り先を決め打ちしない。
- 最初は、自分だけのテスト用トーク(この文書の例では「一括送信」)1 つだけを入れて試す。
- 自分の表示名(返信行の送り手の見分けに使う)は `self_names`(一覧)に書く。

## 操作の前に毎回確かめること(1 つでも違えば止める。やり直さない)
- 非常停止のファイル `%LOCALAPPDATA%\line-desktop-agent\STOP` が無い
- 相手の窓: 窓の番号・LINE.exe・窓の種類(ChatWindow / AllInOneWindow)・題名(Win32 の題名で完全一致)・有効
- LINE がほかの窓(ダイアログ・ポップアップ)を出していない
- 相手の窓が前面に**ない**(前面にあれば本人が使っているので触らない)
- 触る部品がその窓の中にある。ホイールの点が窓の中にある
- 入力欄は最初が空(本人の書きかけには触らない)。入れた文字を読み戻して、確認した文面と一致
- 動いている間は 20 ms ごとに前面を見て、LINE が前に出たかを記録する(`line_front_seen`)

## 押すキーは Enter だけ
- LINE は送信ボタンを UI Automation に出さないので Enter が要る。Enter は LINE の窓への**メッセージ**で、物理のキーではない。ほかのキー(Ctrl+A・Delete・Backspace など)は作っていない(試験で確かめている)。
- 本人の操作の待ち(`idle_s`)は既定で 0。設定ファイルで秒数を入れれば、待つ作りも残してある。

## 記録(`send_ledger.jsonl`)
- 送る前に `sending`、あとで `sent`(最後の行に自分の文面が出た)/ `failed`(送られていない。入れた文字は空に戻した)/ `unknown`(結果が分からない)。
- `sending` と `unknown` が残っている間は、次の送信をすべて断る。自動で送り直さない。目で確かめて `ledger-resolve` する。

## 後片付け
- LINE が前に出たときだけ、本人の窓へ戻す(本人が途中で別の窓に移ったら引き戻さない)。
- 止めたときに入力欄に残るのは「自分が入れた文字そのもの」だけを空に戻す。違う文字なら触らない。

## できないこと(11-10 時点)
- 添付の保存: 「保存 | 名前を付けて保存 | 転送 | Keepメモに転送」は UIA の部品として出ない。
  - 位置は、窓を前に出さずに写す PrintWindow と灰色の文字の帯(`linkbar.py`)で見つけられた。
  - しかし、その位置へマウスのボタンのメッセージを投函しても、右クリックのメッセージ(WM_CONTEXTMENU)を投函しても、何も起きなかった。Qt は本物のボタンの状態を読むとみられる。
  - 本物のマウスを使う作りは、本人の決まり(マウスを使わない)に合わないので作っていない。
  - 段 8 でさらに試した道(MSAA・右クリックのメニュー・画像を見る窓・合成のタッチ・LINE のデータ)も、すべてだめだった。合成のタッチはデスクトップに当たったので、使わない(docs/学んだこと.md 段 8)。
